# Prompt: Punto de venta ligero para cafetería

Actúa como desarrollador/a front-end con experiencia en interfaces accesibles y aplicaciones de punto de venta. Crea una aplicación web ligera para una cafetería tipo kiosco, en español, que permita gestionar ventas de forma rápida y clara.

## Funcionalidad

- Muestra un catálogo de productos con nombre, descripción, precio y categoría.
- Permite buscar productos y filtrar el catálogo por categoría.
- Al seleccionar un producto, agrégalo al ticket y permite cambiar su cantidad o quitarlo.
- Calcula subtotal, descuentos (si los hay) y total automáticamente.
- Permite elegir efectivo, tarjeta o transferencia. Para pagos en efectivo, captura el monto recibido y calcula el cambio.
- Incluye un resumen del turno y una sección de corte de caja con fondo inicial, ventas por método de pago y efectivo esperado.
- Muestra mensajes claros cuando el ticket esté vacío o falten datos para completar una venta.
- Haz que todos los botones y controles visibles funcionen; no dejes acciones que parezcan habilitadas pero sean solo decorativas.

## Diseño y experiencia

- Usa Bootstrap 5 para el sistema de rejilla y los componentes que aporten valor. No uses Bootstrap 6.
- Mantén una identidad kawaii, cálida y amable, apropiada para una cafetería: tonos pastel rosados, lavanda y crema, bordes suaves, tarjetas redondeadas e ilustraciones o emojis discretos.
- Conserva una jerarquía visual clara: catálogo y ticket deben ser fáciles de consultar durante una venta.
- Diseña primero para escritorio y adapta la interfaz a tabletas y móviles sin desbordamientos ni controles difíciles de pulsar.
- Usa etiquetas visibles o accesibles, estados de foco y contraste suficiente para que la interfaz también sea cómoda con teclado y lectores de pantalla.

## Implementación

- Revisa primero los archivos y patrones existentes; mejora el proyecto actual en vez de reemplazarlo innecesariamente.
- Mantén separadas la estructura, los estilos y la lógica, siguiendo las tecnologías y convenciones que ya use el proyecto.
- Si no existe un servidor ni una base de datos, guarda los datos de demostración localmente y explica sus límites; no simules que una venta quedó guardada de forma permanente si no es cierto.
- Evita dependencias innecesarias y no añadas funciones que no estén relacionadas con el flujo de venta.
- Al terminar, prueba la búsqueda, los filtros, el manejo del ticket, los cálculos de pago y el diseño en distintos anchos de pantalla. Resume los archivos modificados y cualquier limitación pendiente.
